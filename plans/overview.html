The real limit is builds, so they queue

Full build: both slots or Small buildSmall build

The build queue (D63). A script on each Mac lets many agents share two build slots. Agents write code, tests, and reviews without building, then build once per batch and run every check that build allows. The queue refuses below 20 GB free or under critical memory pressure, and stops an incremental build that shows more than 20,000 steps. Ship writes it on day 0.

An optional second build Mac (D61). If the MacBook Pro has 32 GB of RAM and 150 GB free (D5), it hosts the sync and a 156 base, one build at a time, with its own queue. The Air then builds its own 156 base once, on day 4, overnight. This needs your OK for agents to SSH to the Pro.

CI release builds are separate. They run on GitHub, take about 1.5 days, and nobody waits on them.

If approval slips

Each day later moves launch one day. The launch build has room for one retry (days 15 to 19).

If the sync isn't merged by day 10, launch waits (D8). A launch on Chromium 154 is the fallback only if it isn't merged by day 30 (11-27), and that must start by 12-15.

Not launch gates: the command bar, sign-in import, design polish, Peek, the little window, and Clear.

No separate server or daemon

A daemon is a program that runs in the background all the time. rac has none. Your tabs and logins already live in the browser, so the browser is the server. While the switch is off nothing listens and nothing uses memory, and every safety check stays in one process.

Node or Bun helpers were rejected: they cost memory, need weaker code-signing rules, and every product that used one ended up running it all the time.

What you give up, compared with a server

  • Agent runs end when rac quits, crashes, or updates.
  • No phone or second Mac can connect.
  • Sessions don't survive a restart.
  • Nothing runs while rac is fully closed.

MCP is the standard way coding agents call tools. The door supports it first, then a rac command line with a skill (D25).

04 How an agent action gets approved

Every step passes the same checks

Each check can stop a step at a confirmation card, and if none does, the step runs.

1

Level

askcarefulauto

How much the agent may do alone. ask confirms every change. careful shows a plan first, then checks each step. auto is the default.

2

Risky list

Steps that always ask, at every level: submitting a form, pressing Enter in a field, password and payment fields, and words like buy, send, post, or delete.

3

Taint rule

Once the agent has read a second site, typing, clicking, or submitting asks first. This closes the "auto hole", where a hostile page makes the agent copy your data into it.

4

Site rules

Your own Always or Never per site. Always lets the agent act there freely. Never blocks every action there. Neither one skips the risky list.

5

Confirm card

Names the site and what the agent read. You allow it once, allow it for this chat, or don't allow it. There is no default button.

What stays free

  • Reading pages, scrolling, waiting, and switching tabs.
  • Going to a URL you typed exactly.
  • Typing your own words from the chat.
  • On a single site, auto stays as free as today.

In code, the risky list is checked before the level, so no level can skip it. Outside agents start read only, and anything they type counts as model text, not your words (plan 05). Launch gate G4 covers the taint rule and its tests.
